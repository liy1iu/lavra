2. Modelo de dados (DER)

Quatro entidades. Usuário representa Produtor ou Técnico, definido pelo atributo perfil. Cada solicitação tem no máximo uma avaliação.

erDiagram
  USUARIO ||--o{ PROPRIEDADE : possui
  USUARIO ||--o{ SOLICITACAO : abre
  USUARIO |o--o{ SOLICITACAO : atende
  PROPRIEDADE ||--o{ SOLICITACAO : origina
  SOLICITACAO ||--o| AVALIACAO : recebe
  USUARIO {
    int id PK
    string nome
    string email UK
    string perfil
    boolean consentimento_lgpd
  }
  PROPRIEDADE {
    int id PK
    string nome
    decimal area_ha
    string cultura
    int produtor_id FK
  }
  SOLICITACAO {
    int id PK
    string assunto
    string descricao
    string urgencia
    string status
    date data_visita
    string relatorio
    int propriedade_id FK
    int produtor_id FK
    int tecnico_id FK
  }
  AVALIACAO {
    int id PK
    int nota
    string comentario
    datetime criada_em
    int solicitacao_id FK
  }

3. Estados da solicitação

Ciclo de vida que sustenta as regras de negócio. Não é possível pular etapas nem voltar.

stateDiagram-v2
  [*] --> Aberta : Produtor envia
  Aberta --> Agendada : Técnico agenda visita
  Agendada --> EmAtendimento : Técnico inicia
  EmAtendimento --> Concluida : Técnico registra relatório
  Concluida --> Avaliada : Produtor envia nota
  Avaliada --> [*]
  EmAtendimento : Em atendimento
  Concluida : Concluída

4. Fluxo principal (sequência)

Da abertura da solicitação até a avaliação final, como no protótipo.

sequenceDiagram
  actor P as Produtor
  participant L as Lavra
  actor T as Técnico
  P->>L: Abre solicitação com propriedade, assunto e descrição
  L-->>P: Status Aberta
  T->>L: Consulta solicitações recebidas
  T->>L: Agenda visita
  L-->>P: Status Agendada
  T->>L: Inicia atendimento
  T->>L: Conclui com relatório
  L-->>P: Status Concluída e avaliação liberada
  P->>L: Envia nota e comentário
  L-->>T: Status Avaliada
